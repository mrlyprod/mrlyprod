Fix a base `b >= 2` and a digit set `F` inside `{0, .., b - 1}` with `0 in F`, and write `fill = card F`. The design `D` is the set of integers whose base-`b` digits all lie in `F`, and its level `L`, written `D_L`, holds the `fill^L` integers below `b^L` with all `L` digits in `F`, leading zeros included; since `0 in F`, `D_L` sits inside `D_(L+1)` and `D` is the union of its levels. A three-term progression is a solution of `x + z = 2y` with `x != z`, and `D` is progression-free when it holds none. The question is which designs are progression-free and how large `fill` gets at a given base; the familiar answer keeps every digit below `b/2`, so that adding two digits never carries, and takes `F` progression-free inside `{0, .., ceil(b/2) - 1}`. This page proves that the whole question is a question about carries, reads the answer off a three-state graph, runs the census to base `40` against brute force, and writes the one door it sees.

## The criterion

- **The signed set.** Write `S = F + F - 2F = {f + g - 2h : f, g, h in F}`, a set of signed integers inside `[-2(b - 1), 2(b - 1)]` holding `0`. It is not symmetric in general: at `F = {0, 1, 3}`, `-5 = 0 + 1 - 2 * 3` lies in `S` and `5` does not, since `5 + 2h` is one of `5, 7, 11` and `F + F = {0, 1, 2, 3, 4, 6}` holds none of them.
- **The carry walk. Proved.** Let `x, y, z` lie in `D_L` with digits `x_i, y_i, z_i`, and put `s_i = x_i + z_i - 2 y_i`, a member of `S`. Then `x + z - 2y = sum_(i < L) s_i b^i`, and this vanishes exactly when the carries `c_0 = 0`, `c_(i+1) = (s_i + c_i)/b` are all integers and `c_L = 0`. Proof. If every carry is an integer, induction gives `sum_(i < j) s_i b^i = c_j b^j` at every `j <= L`, so the sum is `c_L b^L`, which vanishes exactly when `c_L` does. If the sum vanishes, then `b` divides `s_0`, so `c_1` is an integer, and `sum_(1 <= i < L) s_i b^(i-1) + c_1 = 0` is the same statement one digit up; induction closes it with `c_L = 0`. The carries stay in `{-1, 0, 1}`: `abs(s_i) <= 2(b - 1)`, so `abs(c_(i+1)) <= (2(b - 1) + abs(c_i))/b <= (2b - 1)/b < 2` once `abs(c_i) <= 1`, and an integer below `2` in absolute value is one of `-1, 0, 1`. □
- **The carry graph.** Let `G` be the graph on the three states `-1, 0, 1` with an edge `c -> c'` exactly when the label `b c' - c` lies in `S`. The nine labels are `0` on the loop at `0`; `b` on `0 -> 1` and `-b` on `0 -> -1`; `-1` on `1 -> 0` and `1` on `-1 -> 0`; `b - 1` on the loop at `1` and `1 - b` on the loop at `-1`; `-b - 1` on `1 -> -1` and `b + 1` on `-1 -> 1`. The loop at `0` always exists, since `0 = f + f - 2f`, and it is the only edge with label `0`, since `abs(c) <= 1 < b`. By the bullet above, a solution of `x + z = 2y` in `D_L` is exactly a closed walk of length `L` from `0` to `0` in `G` together with digits `x_i, y_i, z_i` in `F` realising each label as `x_i + z_i - 2 y_i`; and every label in `S` is realised by some digits, by the definition of `S`.
- **Nontriviality. Proved.** A closed walk with some label `s_i != 0` always gives a progression: if `x = z` then `x + z = 2y` forces `y = x` and every `s_i = 0`. A closed walk with every label `0` stays at `0` and gives a progression exactly when some digit has `x_i != z_i` with `x_i + z_i = 2 y_i`, a progression inside `F` itself. So `D` holds a progression exactly when `F` does or `G` holds a closed walk from `0` that leaves `0`. □
- **The theorem. Proved.** Let `0 in F`. The design `(b, F)` is progression-free exactly when `F` is progression-free and none of the four closing patterns holds: `b in S` and `-1 in S`; `b in S`, `-b - 1 in S` and `1 in S`; `-b in S` and `1 in S`; `-b in S`, `b + 1 in S` and `-1 in S`. In one line, `D` holds a progression exactly when `F` does, or `b in S` and (`-1 in S` or (`-b - 1 in S` and `1 in S`)), or `-b in S` and (`1 in S` or (`b + 1 in S` and `-1 in S`)). Proof. A closed walk from `0` that leaves `0` exits by `0 -> 1` (label `b`) or `0 -> -1` (label `-b`), walks inside `{-1, 1}`, and returns by `1 -> 0` (label `-1`) or `-1 -> 0` (label `1`). Exit to `1` and return from `1`: the walk inside may be empty, so the pattern is `b, -1`, and it is realised by `0 -> 1 -> 0`. Exit to `1` and return from `-1`: the walk inside enters `-1` from `1` at least once, by the edge `-b - 1`, so the pattern is `b, -b - 1, 1`, realised by `0 -> 1 -> -1 -> 0`. The two exits to `-1` are the mirror patterns `-b, 1` and `-b, b + 1, -1`. The loops at `1` and `-1` lengthen a walk and open none, so every closed walk leaving `0` contains one of the four patterns, and each pattern is a closed walk. With the bullet above this is the theorem. □
- **Three levels decide. Proved.** The four patterns are walks of length `2` or `3`, and a progression inside `F` is one of length `1`; so `(b, F)` is progression-free exactly when `D_3` is, whatever the level. The criterion reads six memberships in `S`, those of `1, -1, b, -b, b + 1, -b - 1`, and nothing else about `F`.
- **Without the digit `0`.** The hypothesis `0 in F` pads the three numbers to one length with a digit of `F` and nests the levels. Without it, `x < y < z` may have three different lengths, and the walk carries a second coordinate, which of the three are still running: the labels of a step lie in `F + F - 2F` while all run, in `F - 2F` once `x` has ended, and in `F` once `y` has too, with `c_L = 0` at the end as before; the three-state graph becomes a nine-state one and the patterns are read off it the same way. At a fixed level nothing is lost either way: `D_L(F)` is the translate of `D_L(F - min F)` by `(min F)(b^L - 1)/(b - 1)`, and progressions survive translation.
- **The place slot.** In the three-slot language of [beneath](../../beneath/notes/beneath.md), a design accepts every word over `F` and places the word `d_0 d_1 ..` at `sum d_i b^i`; `x + z = 2y` is an equation between placed values, and the carry is the one way the place slot lets the digit at one position speak to the next, so the criterion is a statement about the place slot, read through the accept slot's digit set alone: the arithmetic of place at base `b` collapses to six memberships in `F + F - 2F`.
- **The no-carry case.** When neither `b` nor `-b` lies in `S`, no edge leaves `0`, and the design is progression-free exactly when `F` is. Digits below `b/2` give `S` inside `[-(b - 1), b - 1]` and so this case, which is the half-base construction; the case is wider than that construction, since it asks only that `F + F` miss `b + 2F` and `2F - b`, and the census below finds a base where the width pays.

## The census

- **The lift of a cyclic set. Proved.** Call `F` progression-free mod `b` when `f + g = 2h` mod `b` has no solution in `F` besides `f = g = h`; at even `b` this counts `f = g != h` with `h = f + b/2`, the convention of [A304884](https://oeis.org/A304884). Then `F` is progression-free mod `b` exactly when `F` is progression-free in the integers and neither `b` nor `-b` lies in `S`: since `abs(f + g - 2h) <= 2(b - 1) < 2b`, the congruence holds exactly when `f + g - 2h` is one of `-b, 0, b`; the value `0` with `f = g` forces `h = f`, so a nontrivial solution of value `0` is a progression in `F`, and a solution of value `b` or `-b` is never `f = g = h`. So the no-carry case of the criterion is exactly the lift of a set progression-free mod `b` to a digit design, which the criterion then proves progression-free at every level: the digit lift of a cyclic progression-free set. □
- **The box. Verified.** Every `F` with `0 in F` and `F` progression-free in the integers, at every base `2..40`, built by adding digits in increasing order and refusing a digit that closes a progression in `F`; `89442` such sets at base `27`, `3` at base `3`. - **Where the half-base construction loses. Verified.** At four bases in the box the cyclic lift holds more digits than any set below `b/2`: base `19`, six against `r_3(10) = 5`, by `18` digit sets, the least `{0, 1, 3, 12, 14, 15}`; base `35`, nine against `r_3(18) = 8`, by `54` sets; base `37`, ten against `8`, by `40` sets; base `39`, ten against `9`, by `40` sets. At base `19` the digits `12, 14, 15` sit above `b/2` and the set pays nothing for them: `F + F = {0, 1, 2, 3, 4, 6, 12, .., 18, 24, 26, .., 30}` misses `19 + 2F = {19, 21, 25, 43, 47, 49}` and `2F - 19 = {-19, -17, -13, 5, 9, 11}`, so neither `19` nor `-19` lies in `S` and no carry ever leaves `0`.
- **A carry never wins in the box. Verified**, and open beyond it. At every base `2..40` the maximum is reached by a digit lift of a cyclic set: the largest progression-free design whose carry graph has an edge out of `0` never exceeds the largest lift. At bases `2, 3, 5, 7` no such design exists and at bases `9, 19, 21, 25, 27, 35, 37, 39` it falls one or two digits short, so at those twelve bases every maximiser is a lift; at every other base it ties, and some maximisers carry an edge, `{0, 2}` at base `4` the least of them, `2` of the `182` at base `40`. The bases where every maximiser is a lift are exactly `2, 3, 5, 7, 9, 19, 21, 25, 27, 35, 37, 39`, read off the lift column. Designs with such an edge exist from base `4` on, `{0, 2}` at base `4` being the least: `4 = 2 + 2 - 0` lies in `S`, and the walk `0 -> 1` can never return, since `-1`, `1`, `-5` and `5` all miss `S`. Every digit set inside `2Z` is of this kind at an even base, since `S` is then even and every return label is odd; it holds at most `r_3(b/2)` digits, the half-base count.
- **What stays open. Conjecture.** At every base the largest progression-free design is a digit lift of a largest set progression-free mod `b`, so its fill is [A304884](https://oeis.org/A304884) at that base. The evidence is the box `2..40` and nothing else; a design with a carry edge that beats the lift at some base would refute it, and the first base to look at is one where the cyclic maximum is small against `r_3(ceil(b/2))`.
- **Dimension. Verified.** The dimension `log(fill)/log(base)` of the largest progression-free design stays at or below `log 2/log 3 = 0.6309..` at every base `2..36`, with equality exactly at `3`, `9` and `27`, where the maximisers include the digit sets `{0, 1}`, `{0, 1, 3, 4}` and `{0, 1, 3, 4, 9, 10, 12, 13}` of the Stanley sequence [A005836](https://oeis.org/A005836) read in blocks of one, two and three ternary digits; at base `27` the half-base construction already ties it. Base `37` is the least base where a digit design beats it: ten digits, `{0, 1, 3, 7, 17, 24, 25, 28, 29, 35}` the least of `40`, dimension `log 10/log 37 = 0.6376..`, a progression-free set of integers of counting dimension above the Stanley sequence's, by a lift of a largest progression-free subset of `Z_37`; bases `38`, `39` and `40` fall back below. That the exponent passes `log 2/log 3` at some base is no surprise, since the cyclic maximum grows like `b` up to a factor `exp(-c sqrt(log b))` by Behrend's construction; the census only says where.

## The neighbours

- **Salem-Spencer and Behrend.** [Salem and Spencer 1942](https://doi.org/10.1073/pnas.28.12.561) and [Behrend 1946](https://doi.org/10.1073/pnas.32.12.331) are the two classical constructions of large progression-free sets of integers; their citations are read at PubMed Central, their texts sit behind page images and are not read here. Behrend's bound is read in the restatement of [Elsholtz, Hunter, Proske and Sauermann 2024](https://arxiv.org/abs/2406.12290): `r_3(N) >= N 2^(-(2 sqrt 2 + o(1)) sqrt(log_2 N))`, which their Theorem 1.1 improves to the constant `2 sqrt(log_2(24/7)) = 2.667..`, and the bound `(p/2)^n` over `F_p^n` is the one they attribute to the constructions of the 1940s and pass with `(0.54 p)^n`. Neither construction is a digit design: Behrend's digits are tied by a sphere and theirs by a slice.
- **Digit designs are the product constructions.** A digit design at level `L` is a product set `F^L` inside `Z_b^L` read as integers, and the two digit constructions the literature uses, digits below `b/2` and the digit lift of a cyclic set, are both the no-carry case of the criterion. Over `F_q^n`, [Hametner and Tyrrell 2026](https://arxiv.org/abs/2606.12194), abstract read, prove that no product of a fixed solution-free set is asymptotically optimal for any translation-invariant equation of genus one, cap sets included; the census above is the census of the product constructions at small base and competes with no Behrend-type exponent: its dimensions are counting dimensions of product sets, which pass `log 2/log 3` at base `37` and tend to `1` with the base by Behrend's bound applied to `r_3(ceil(b/2))`.
- **Stanley sequences.** The Stanley sequence `S(0, 1)`, [A005836](https://oeis.org/A005836), the integers with no digit `2` in base `3`, is the design `(3, {0, 1})` and the greedy progression-free sequence from `0, 1`; its record, read at the mirror, carries Craigen's comment that it is the lexicographically earliest increasing progression-free sequence and Sloane's naming it `S(0, 1)`, and links the 1978 memo of Odlyzko and Stanley, Some curious sequences constructed with the greedy algorithm, whose scan is read here for its listing only. [Rolnick 2017](https://arxiv.org/abs/1408.1940), abstract read, defines the regular Stanley sequences by a local structure that implies the growth Odlyzko and Stanley conjectured for the structured class; [Moy and Rolnick 2016](https://arxiv.org/abs/1502.06013), abstract read, define the modular and the basic Stanley sequences, the basic ones sums of subsets of a basis such as the powers of `3`. Read at source in the arXiv text, their Definition 2.2 and Theorem 2.4: a modular set `A` modulo `N` holds `0`, is `3`-free modulo `N` and covers every residue outside it by some `2y - z` with `y, z in A`, and its Stanley sequence is `S(A) = A + N S(0)`, one base-`N` digit from `A` under the base-`3` Stanley digits `{0, 1}` of `S(0)`: a mixed-radix digit design and not the cyclic lift of this page, which repeats `A` at every base-`N` place. At their Example 2.5, `A = {0, 1, 7, 8}` modulo `10`, the sequence holds `30` and not `70` and the lift holds `70` and not `30`; both are progression-free, the lift by the criterion since neither `10` nor `-10` lies in `S`, and only theirs is greedy. In the words of this page the Stanley sequence is the one digit design the greedy algorithm writes, read at base `3^k` with the `2^k` digits of the maximisers at bases `3`, `9` and `27`, and no design at a base below `37` passes its dimension.
- **Cyclic groups.** [A304884](https://oeis.org/A304884), record read at the mirror, is the largest size of a subset of `Z_n` with no nontrivial three-term progression, `x, x, x` the only trivial ones, with terms to `n = 79`; its link names Halbeisen and Halbeisen 2005, Avoiding arithmetic progressions in cyclic groups, not read here. The census recomputes its terms at `n = 3..40` twice, by a search mod `n` and as the no-carry column of the criterion.
- **The empirical side.** [Gasarch, Glenn and Kruskal 2025](https://arxiv.org/abs/2501.01634), abstract read, survey the constructions and test which of them produce the largest progression-free subsets of `{1, .., n}` at actual `n`; the census here answers the same question for digit designs only, where the answer in the box is the cyclic lift.
- **The two frontier methods.** [Elsholtz, Hunter, Proske and Sauermann 2024](https://arxiv.org/abs/2406.12290), read at source in Theorems 1.1 and 1.2, Proposition 2.2 and Definition 4.1, improve Behrend's constant through a planar building block, the door below. [Hametner and Solymosi 2026](https://arxiv.org/abs/2609.13972), abstract read, turn a finite certificate into large solution-free sets by combinatorial degenerations, the method of [Christandl, Fawzi, Ta and Zuiddam 2022](https://arxiv.org/abs/2111.08262), abstract read, for corner-free sets, and reach `N^0.5608..` for `3x + y - 2z - 2w`; read at source, their certificate for `x - 2y + z` is the block inequality of the door with a strict margin in place of the squared distance, the two agreeing on every finite grid, as the door shows.
- **What is new here, and what is not.** The carry automaton of an addition is a standard object, and the tree reads one on [kummer](../../kummer/notes/kummer.md) and one on [beneath](../../beneath/notes/beneath.md); the digit lift of a cyclic progression-free set is the product construction of the literature. What this page adds is the exact criterion with its two carry edges that leave `0` and never return, the finite check at level `3`, the equivalence of the no-carry case with progression-freeness mod `b`, and the census that says a returning-free carry never pays in the box; no claim of priority is made on any of it, the surveys above being read in abstract only. A digit design is a base-`b`-recognisable set, and every first-order question about such sets, the existence of a three-term progression included, is decided mechanically by the theory of automatic sequences as implemented in Walnut ([Mousavi 2016](https://arxiv.org/abs/1603.06017), abstract read); the value of the criterion is that it is explicit, six memberships in `S` read off `F` by hand, not that it decides.

## The door: the planar block

- **The block, as read at source.** [Elsholtz, Hunter, Proske and Sauermann 2024](https://arxiv.org/abs/2406.12290), Proposition 2.2: for `0 < eps < 1` there is a measurable `T` inside `[0, 1)^2` with `mu(T) >= 7/24 - eps` and a measurable `f: T -> [0, 100/eps^2]` with `f(x) + f(z) >= 2 f(y) + (x_1 - z_1)^2 + (x_2 - z_2)^2` at every `x, y, z in T` with `x + z = 2y` mod `1` in both coordinates, `x = z` not excluded, the differences taken between the representatives in `[0, 1)` and not on the torus. Their `T` is three polygons, `T_1 = {a in [1/2, 1), b in [0, 1), 2/3 < a + b <= 7/6}` of area `7/36`, `T_2 = {a in [1/2, 1), b in [0, 1/2), 7/6 + eps <= a + b <= 17/12}` of area `15/288 - eps/2` at least, and `T_3 = {a in [0, 1/2), b in [1/2, 1), 7/6 + eps <= a + b <= 17/12, 2a + b >= 3/2 + eps}` of area `13/288 - eps/4` at least, with `f(x) = (24/eps^2)(x_1 + x_2)^2 + 6 g(x_1)`, `g(t) = t^2` on `[0, 1/2)` and `(t - 1/2)^2` on `[1/2, 1)`. Proposition 2.1 turns `n/2` blocks into a measurable `S` in `[0, 1)^n` of measure at least `10^-5 delta^2 n^-3 (7/24)^(n/2)` in which `x + z = 2y` mod `1` forces `abs(x_i - z_i) < delta` at every coordinate, by a slice of the sum of the `f` values; Theorem 1.1 follows by the embedding `r -> a + r/m_i` mod `1` of a product of prime-power cyclic groups at `delta = N^(-1/n)/4`, which costs `N^(-2/n)`, and `n` within `2` of `2 sqrt(log_2 N/log_2(24/7))`. In their words the construction is somewhat ad-hoc, `7/24` can plausibly be improved by a better `T`, and a better block with larger area carries over to the constant. They pose no question; the door is open by their invitation.
- **From a block to the constant.** Let a block live in `[0, 1)^k` with `mu(T) = alpha` and the inequality carrying `sum_i (x_i - z_i)^2`. Their count with `n/k` blocks gives the exponent `(n/k) log_2(1/alpha) + 2 log_2 N/n`, least at `n = sqrt(2k log_2 N/log_2(1/alpha))`, so `r_3(N) >= N 2^(-(C + o(1)) sqrt(log_2 N))` with `C = 2 sqrt((2/k) log_2(1/alpha))`. At `k = 2` and `alpha = 7/24` this is their `2.667..`; at `k = 1` and `alpha = 1/2` it is Behrend's `2 sqrt 2`, and the block is `T = [0, 1/2)` with `f = 2x^2`, since `x + z = 2y` wraps nowhere there and `2x^2 + 2z^2 - (x + z)^2 = (x - z)^2`. Over `F_p^n` and `Z_m^n` the constant is `c = alpha^(1/k)`, `sqrt(7/24) = 0.540..` at theirs. The `k`-form is this page's reading of their count and is proved here for no `k` but `2`, where it is theirs.
- **The discrete block problem.** Fix `k` and `m` and the grid `G = {0, .., m - 1}^k`. Variables: `t_v in {0, 1}` at every `v in G`, the block `T = {v : t_v = 1}`, and reals `f_v >= 0`. Constraints: at every `x, y, z in T` with `x + z = 2y` mod `m` coordinatewise, `x = z` allowed, `f_x + f_z >= 2 f_y + sum_i (x_i - z_i)^2/m^2`, the differences the plain differences of grid coordinates. Objective: the largest `alpha_m = card T/m^k`. This is the EHPS form; the HS form of [Hametner and Solymosi 2026](https://arxiv.org/abs/2609.13972), read at source, forbids the solution `x = z != y`, which is nontrivial in their sense whenever `2` does not kill the group, and asks only for a strictly positive margin. Both forms are run by [lab/py/block-search](../lab/py/block-search/).
- **The potential is a peeling order. Proved.** [Elsholtz, Proske and Sauermann 2024](https://arxiv.org/abs/2401.12802), read at source, call `S` in `Z_m^d` non-mid-point reducible (their Definition 2.3) when every nonempty subset holds a point that is the midpoint of no two distinct points of the subset, that is when `S` empties under repeated removal of such points; the class version below is that notion with the half-period pairs EHPS keep. Call two grid points classmates when `2x = 2y` mod `m`, that is `y - x` in `(m/2){0, 1}^k` at even `m` and `x = y` at odd `m`. On a finite grid the following are equivalent for a set `T`: (a) some `f` meets the EHPS constraints; (b) some `g: T -> R` is constant on classmates and has `g_x + g_z > 2 g_y` at every triple with `x != z`; (c) `T` is class-peelable: repeatedly remove from the live set a whole class none of whose live members is the midpoint `y` of a live pair `x != z`, and reach the empty set. Proof. (a) to (b): at `x = z != y` the constraint reads `f_x >= f_y`, and `(y, x, y)` is a triple too since `2y = 2x`, so `f` is constant on classmates; at `x != z` the margin `sum (x_i - z_i)^2/m^2` is positive. (b) to (a): the triples are finitely many, so `c = min (g_x + g_z - 2 g_y)/sum (x_i - z_i)^2` over `x != z` is positive, and `f = g/c` shifted to be nonnegative meets every constraint. (b) to (c): a class of largest `g` among the live classes is removable, since a live midpoint `y` in it of a live pair `x != z` would give `g_x + g_z > 2 g_y >= g_x + g_z`; the restriction of `g` keeps (b), so the removal continues to the empty set. (c) to (b): put `g = 3^(R - 1 - r)` on the class removed in round `r` of `R`. In a triple with `x != z` the ends are never classmates of `y`, since `x + z = 2y` and `2x = 2y` give `z = x`; if `y` were removed no later than both ends, it would be a live midpoint of a live pair at its removal; so some end is removed strictly before `y`, `g_x + g_z - 2 g_y >= 3 g_y - 2 g_y > 0`. □ Removing points never creates a midpoint, so the removable classes only grow and the greedy order is confluent; its fixpoint, the core, is a set in which every class holds a live midpoint, and a set is peelable exactly when it contains no core. Three consequences. The margin's shape plays no part on a grid: the squared distance, the margin `1` of the HS form and any positive weight give the same sets. At odd `m` the two forms coincide. At even `m` the HS form holds at most one point per class, so at most `m^k/2^k` points, and at `k = 2` the quarter square `{0, .., m/2 - 1}^2` with `g = x_1^2 + x_2^2`, inside which `x + z = 2y` never wraps, attains `1/4`: the HS form is exactly `1/4` at every even `m` and `k = 2`, below `7/24`, and the half-period pairs EHPS keep are what carry their block.
- **Every grid bounds every block. Proved.** The shifted grid is Elsholtz, Proske and Sauermann's Fact 3.7, which they run from their region of area `7/24` to a reducible set of at least `7 m^2/24` points (Proposition 2.5); here it runs from every block. Let `(T, f)` be any planar block, `T` measurable in `[0, 1)^2`, `f >= 0` with the EHPS inequality at every triple, bounded or not. For `a` in `[0, 1/m)^2` the shifted grid `{v/m + a}` lies in `[0, 1)^2`, its triples `v + w = 2u` mod `m` are triples `x + z = 2y` mod `1` of `T`, and `(v_i/m + a_i) - (w_i/m + a_i) = (v_i - w_i)/m` are the representatives' differences, so `f` restricted meets the grid constraints; and the expected count of grid points in `T` over a uniform `a` is `m^2 mu(T)` by Fubini, so some `a` gives at least `m^2 mu(T)` points. Hence `mu(T) <= alpha_m` at every `m`, for every block, with no loss; EHPS's blocks give `alpha_m >= 7/24 - eps` at every `eps`, so `alpha_m >= 7/24`. Also `alpha_(jm) <= alpha_m`: a set at `jm` splits into the `j^2` cosets `{jv + e}`, each a set at `m` with the triples and distances scaled, so one coset has density at least the whole. So `inf_m alpha_m` along the divisibility order bounds every planar block, the kill condition reads `alpha_m -> 7/24`, and an exact `alpha_m` is a theorem about every planar block. □
- **One dimension. Proved and Verified.** At `k = 1`, `alpha_m = (m + 1)/(2m)` at odd `m`, `1/2 + 1/m` at even `m` in the EHPS form, `1/2` in the HS form. Upper bound: at the top class of `g`, a point `x` with `2y - x in T` is the end of a triple through `y`, so `x` is a classmate of `y`, `card (T n (2y - T)) <= card class`, and `2 card T - card class <= m`. Lower bound: `{0, .., (m - 1)/2}` with `g = x^2` wraps nowhere; `{0, .., m/2}` with `g = x^2` except `g_0 = g_(m/2) = (m/2)^2` has its only wrap at `x = z = m/2`; `{0, .., m/2 - 1}` with `g = x^2`. The exact solver returns these numbers at `m = 2..20`. □ So the one-dimensional control, that `k = 1` never passes `1/2`, is false by exactly `1/m`: the grid slack of a block is `O(1/m)`, and a planar reading has to subtract it.
