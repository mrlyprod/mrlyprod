# block-exact

- The exact grid optimum `alpha_m` of the discrete block problem of [progressions](../../../notes/progressions.md), section The door, at odd prime `m`: the largest peelable subset of `Z_m^2`, found by enumerating every peelable set of a target size or more up to affine symmetry. The verb `climb` searches for large peelable sets in `Z_m^d` at any `m` and `d`. The verb `witness` prints the first maximiser `optimum` lists, the least by bit mask, as the JSON of the census figure of [method](../../../../method/).
- `optimum` and `census` run at odd prime `m` only; `climb` runs at every `m` and dimension `d`. At odd `m` the classes are single points and a set admits the potential exactly when it peels: remove repeatedly a live point that is the midpoint of no live pair `x != z`, until empty. The affine group `AGL(2, m)`, of order `m^2 (m^2 - 1)(m^2 - m)`, preserves midpoints, and its two-point stabiliser fixes a line pointwise and is transitive off it, which the canonicity test uses. Even `m` (classes of four points) and composite `m` (no transitive point stabiliser) are not run.
- No dependency: one file, `std` only, `8` threads.

## THE METHOD

- A point `(a, b)` is the index `a m + b`; a set is a `u128` mask. The canonical set of an orbit is the one whose sorted index list is lexicographically least; it contains `0` and `1 = (0, 1)`.
- Orderly generation. The canonical set minus its largest index `t_k` is canonical: if `h T' < T'` with the first difference at `p` (so `p` in `h T'`, not in `T'`), then at `p < t_k` the set `h T` beats `T` at `p` or at `h(t_k)`, and `p >= t_k` forces `h T' = T'`. Peelability is hereditary, since removing points never creates a midpoint. So the depth-first search that adds a larger index and keeps a child only when it peels and is canonical visits every orbit of peelable sets exactly once.
- `canonical`: for every ordered pair `(t, t')` of the set, the line `t + c (t' - t)` is read as an `m`-bit pattern `F` and compared with the set's pattern on the line `{(0, c)}`. `F` lexicographically smaller: some affine map beats the set. `F` larger: no map through this pair does. `F` equal: the `m^2 - m` matrices `A` with `A (t' - t) = (0, 1)` are each applied to the off-line points and compared; a map that fixes the set is counted, which gives the automorphism group and the orbit size.
- The bound. At a node `S` the candidate list `C` holds the indices above `max S` whose addition keeps `S` peelable; by heredity every peelable descendant `T` lies in `S u C`. A line `L` meets a peelable set in a peelable subset of `Z_m`, since the midpoint of a pair on `L` lies on `L`. So `card T <= sum_L maxpeel[S n L][(S u C) n L]` over the `m` lines of a parallel class, the least over the `m + 1` classes, where `maxpeel[f][a]` is the largest peelable `P` of `Z_m` with `f <= P <= a`, a `2^m x 2^m` table. A node whose bound falls below the target is cut.
- The target is a lower bound: the best of `200` greedy builds in random order, or `--target` if larger. If nothing of the target size is found the target drops by one and the run repeats, so the enumeration of every set of the final target or more points is complete, and its largest member is `alpha_m m^2`.
- The certificate of a maximiser: the peel rounds, `g = 3^(R - 1 - r)` on the point removed in round `r` of `R`, checked on every triple `x + z = 2y`, `x != z`, in exact integers.
- `climb`: local search for a large peelable set in `Z_m^d`, any `m`, any `d` with `m^d <= 65536`, on `8` threads. A set peels exactly when its points can be inserted one at a time, each the midpoint of no two distinct earlier points (the reverse of a peel order), so a point that is the midpoint of no pair of the set always joins it. A build inserts such points one by one, the next the one that newly covers the fewest free points, ties broken by noise; then kicks: remove one to three points, or force one point in and strip random core points until the set peels, or from the thread's best remove four to twelve; after each kick the free insertion runs again and every outside point is tried by a full peel test. At even `m` a point is the midpoint of `x != z` when `2y = x + z`, which a whole class of cousins shares, so cousins peel in the same round; this is the non-mid-point reducibility of Elsholtz, Proske and Sauermann at every `m`. The best set is peeled in rounds, `g = 3^(R - 1 - r)` is checked on every triple `x + z = 2y`, `x != z`, inside it, and every slice of `T^2` by the sum of `g` is checked progression-free in `Z_m^(2d)` by brute force over pairs. The run is seeded (`--seed`) and time-capped, so the set found can differ between runs, and the sets are printed in full below.
- The frontier: the tree is cut at the first depth with `64` canonical nodes or more, and the subtrees are shared by `8` threads; the counts do not depend on the schedule.

## THE CONTROLS

- `cargo test`: the `climb` peel against a brute-force one-point-at-a-time peel on `1800` random sets at `m = 4, 5, 6, 7`, `d = 2` and `m = 3, 4`, `d = 3`; `peelable` against a reflection-based peel on `2700` random sets at `m = 3, 5, 7`; the one-dimensional table gives `(m + 1)/2` at `m = 3, 5, 7, 11`; at `m = 3` the orderly census equals the brute force over all `512` sets in orbits, in sets and in sets containing the origin (`57`); the line bound is never below the size of a peelable `10`-set at `m = 5` on `200` random sets.
- `census 3 5`: `5` and `168` orbits, `172` and `1346226` sets, `57` and `417581` containing the origin, the last two the counts of the Python depth-first enumeration in [block-search](../../py/block-search/).
- `optimum 3 5`: `4/9` and `10/25`, with `1` and `9` maximisers up to symmetry.
