# block-search

- The discrete block problem of [progressions](../../../notes/progressions.md), section The door: on the grid `{0, .., m - 1}^k` a set `T` and a potential `f >= 0` with `f(x) + f(z) >= 2 f(y) + sum_i (x_i - z_i)^2 / m^2` at every `x, y, z in T` with `x + z = 2y mod m`, the `x = z` case kept (EHPS form), or with `x = z != y` forbidden (HS form); the largest `card T / m^k`.
- The oracle is combinatorial: on a finite grid the potential exists exactly when `T` is class-peelable, the classes being the cosets of `{h : 2h = 0}`, a class removable when none of its live members is the midpoint `y` of a live pair `x != z`; the certificate is `g = 3^(R - 1 - r)` on the class removed in round `r` of `R`, checked in exact integers. The linear program (HiGHS through `scipy.optimize.linprog`) cross-checks it and returns `f` with the squared-distance margin and the least `max f`; on an infeasible `T` the max-margin dual returns the Farkas weights, and the greedy fixpoint returns the core, a set in which every class holds a midpoint of a live pair.
- `controls`: the EHPS block `T_1 u T_2 u T_3` rasterised at `m = 12, 24, 36` with `eps = 1/(4m)` and the best of `16` sub-grid shifts, its count against `7 m^2/24`, peelability, the linear program, and EHPS's own `f = (24/eps^2)(x_1 + x_2)^2 + 6 g(x_1)` checked as a feasible point in exact rationals; `k = 1` exact optima at `m = 2..20` by the lazy-core solver against `(m + 1)/2` at odd `m`, `m/2 + 1` at even `m` in EHPS form and `m/2` in HS form; `144` random sets at `k = 2` on which the peel oracle, the linear program and the sign of the max margin must agree; one infeasible set at `m = 6` with its minimal core and its Farkas weights, balance and weighted distance printed.
- `exact --lo a --hi b --cap s`: the exact optimum at `k = 2` by lazy cores: a 0/1 program over `t_v` with one cut `sum_K t_v <= card K - 1` per known core `K` and its images under translations, coordinate swaps and negations, solved by `scipy.optimize.milp`; the solution is peeled, its minimal core added, until the solution is peelable (then it is optimal) or the cap falls (then the last program value is an upper bound). Prints the bitmap, `alpha`, `C(alpha) = 2 sqrt(log_2(1/alpha))`.
- `brute --m ...`: every peelable set containing the origin by depth-first search with hereditary pruning, the largest printed; independent of the solver.
- `search --m ... --seconds s`: local search per `m`, EHPS form and HS form: seeds are the rasterised EHPS block and random class-order greedy builds (a class is added with its largest subset no member of which is a midpoint of a live pair); then extension by every outside point the oracle accepts, and perturbation (force one to three outside points in, remove core points until peelable, re-extend), plateau moves accepted, `30` stale rounds per seed. Prints the best with its bitmap, `alpha`, `C`, `alpha^(1/2)`, the peel depth and the least `max f`; `--save name.json` writes `T`, its coordinates, the linear-program `f` and the integer peel certificate.
- `refine --load name.json --factors j .. --repair s`: dilates each saved `T` `j`-fold to `Z_(jm)^2` (each point a `j x j` square), tests peelability, prints the minimal core when it fails, and repairs by stripping and local search for `s` seconds.
- `stable --m ... --factors j ..`: the search with the oracle "peelable and every `j`-fold dilation peelable", for unions of `1/m`-squares; `--test` dilations are tried on the winner.
- `lift --m ... --n ...`: at odd `m` takes the exact block (`m <= 6`) or the saved search best, forms `S_s = {x in T^(n/2) : sum_j 2 g(x_j) = s}` with the integer certificate `g`, picks the largest slice and checks it progression-free in `Z_m^n` by brute force over pairs, against the bound `card T^(n/2) / (max g . n + 1)`.

## RUN

- `uv run python research/progressions/lab/py/block-search/block.py controls`, `27` seconds.
- `uv run python research/progressions/lab/py/block-search/block.py exact --lo 2 --hi 8 --cap 90`, `232` seconds, `m = 7, 8` not closed; `--lo 7 --hi 7 --cap 280` does not close `m = 7` either.
- `uv run python research/progressions/lab/py/block-search/block.py brute --m 3 4 5`, `11` seconds.
- `uv run python research/progressions/lab/py/block-search/block.py search --m 12 --seconds 20 --save m12.json`, `40` seconds; `--m 24 36 --seconds 150 --save m24-36.json`, `602` seconds in two runs of `300`; `--m 5 7 8 9 10 11 13 14 15 16 17 18 19 20 21 23 --seconds 12`, `264` seconds; `--m 7 9 11 13 --seconds 45 --save odd.json`, `180` seconds; `--m 18 30 --seconds 100 --ehps-only --save m18-30.json`, `200` seconds; `--m 48 --seconds 280 --ehps-only --save m48.json`, `294` seconds.
- `uv run python research/progressions/lab/py/block-search/block.py refine --load m12.json --factors 2 3 --repair 45`, `92` seconds.
- `uv run python research/progressions/lab/py/block-search/block.py stable --m 12 --factors 2 3 --test 4 6 --seconds 150 --save stable12.json`, `214` seconds.
- `uv run python research/progressions/lab/py/block-search/block.py lift --m 5 7 --n 4 6 --load odd.json`, `70` seconds, and `--m 9 11 13 --n 4 --load odd.json`, `2` seconds.
- Every check asserts; `--save` writes the named JSON beside this file, nothing else is written; the searches are seeded (`--seed 1`) and reproducible up to the time cap.

## THE ROUNDING

- Peelability, the cores, the integer certificates and the EHPS feasibility check are exact; the linear programs run in HiGHS at its defaults and print their least slack (`-6e-14` at worst on the controls), the sign of the max margin agreeing with the exact oracle on every tested set.
- `alpha` prints to five decimals, `C` and `alpha^(1/2)` to four, as readings of exact fractions.
