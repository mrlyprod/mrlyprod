# lag-bias

- Does the path count `r_Q(n) = [z^n] prod_(j < L) Q(z^(b^j))` of [dilations](../../../notes/dilations.md) predict, past the linear theorem, the gradient energy at lag `n` of a ReLU dilated stack at initialisation and the time a GELU stack takes to learn lag `n`, against distance and popcount; and does the flat initialisation `Q = 1 + z` remove the popcount bias of the residual stack.
- `field` draws `--draws` random stacks per arm, `200` registered, `C = 16` channels, base `2`, a fresh Gaussian input of length `2^L` and a readout `u` uniform on the unit sphere per draw, one backward from the last output; the energy `E(n)` is the mean over draws of the squared input gradient at lag `n` summed over the `C` input channels, so the linear theorem reads `E(n) = r_Q(n)`. Float64 on cpu. Arm `i` and activation `a` (`0` linear, `1` ReLU) draw from the generator seeded `--seed + 2i + a`, `--seed 17` registered; `--arms` picks arms by id, `pure`, `c2`, `c0.5`, `c0.125`, `flat`. Each run is stored under its draws and seed with the per-lag `E` and `SE`, so the statistics recompute from the cache.
- Arms: pure `K = 3` at `L = 8`, every tap `C sigma^2 = 2` under ReLU and `1` linear, `Q = 1 + z + z^2`, lags `0..255`, `r = s(n + 1)`; residual `h' = h + act(W_0 h_t + W_1 h_(t - 2^j))` at `L = 10` with `C sigma^2 = 2c` under ReLU and `c` linear on both taps, `c` in `2, 1/2, 1/8`, `Q = (1 + c) + c z`, lags `0..1023`; flat, the same block with `W_0 = 0` and `C sigma^2 = 2` under ReLU, `1` linear, on `W_1`, `Q = 1 + z`. Each arm runs ReLU and linear; linear is the control.
- Per arm `field` prints the median relative error `|E - r|/r`, the correlation of `log E` with `log r`, the slope of `log E` on `log r`, the share of lags with `|z| > 3`, `z = (E - r)/SE` over the draws; the same correlation and median relative error for two fitted rivals, a Gaussian in `n` (a quadratic in `n` fitted to `log E` by least squares, the Luo shape) and a power of distance (`log E` linear in `log(n + 1)`); and for the residual and flat arms the slope of `log E` on `popcount(n)` against `log(c/(1 + c))`, with its `R^2`; mean `E/r` by `r` for the pure arm, with its value at `r = 1` and range over `r >= 24`, and by popcount for the others.
- `learn` trains a GELU stack, `K` taps at dilations `2^j`, `L = 8` levels, `C = 16`, no bias, the first level `1 -> C`, a linear readout `C -> 1`, He fan-in init `sigma^2 = 2/(K C_in)`, on `y_t = sum_(n in S) x_(t - n)`, `x` standard Gaussian, `S = 129, 143, 144, 151, 168, 214, 254, 255`, batch `32`, length `512`, loss on `t >= 255`, a fresh batch a step, at most `3000` steps, float32 on cpu with `4` threads, each level a matrix product of the `K` shifted copies, `8` ms a step against `24` for `conv1d` and `15` to `23` on `mps`. Every `--every` steps, `25` registered and `1` amended, it reads the filter `f(n) = dy_511/dx_(511 - n)` at `8` fixed Gaussian probes, averaged; the learn time of lag `n` is the first read with `f(n) >= 0.5`; a lag never reached is capped and ranked above the cap.
- `S` has `r = s(n + 1) = 7, 4, 19, 7, 29, 29, 8, 1` and popcount `2, 5, 2, 5, 3, 5, 7, 8`: equal `r` at different popcount in `129, 151` and `168, 214`, adjacent lags at different `r` in `143, 144` and `254, 255`; Spearman of `r` with `n` is `0.072`, with popcount `-0.429`.
- Optimisers: Adam at lr `1e-3`, and plain SGD at the largest lr in `1, 0.3, 0.1, 0.03, 0.01` whose `100`-step run at seed `99` on the same stack keeps every loss finite and below `10` times the first, and ends with its last `25` losses below its first `25` on average. Seeds fix init and data, paired across optimisers: `0, 1, 2` registered, `3` rather than `5` to stay inside the machine budget if every run capped. The amended rule, `--tune strict`, asks the same loss test of the probe seeds `97, 98, 99` over `300` steps, with seeds `0..4`.
- Stacks: `K = 3` (Stern), `K = 2` (`r = 1` on every lag, scored against the `K = 3` count `s(n + 1)`), `K = 4` (`r_4(n) = floor(n/2) + 1` below `2^L`, monotone in `n`, so its score against `1/r_4` is minus its score against distance).
- Per stack and optimiser `learn` prints each lag's learn times over seeds and their median, and the Spearman correlation of the median learn time with `1/r`, `n` and popcount, the share of `10000` shuffles of `r` over `S` whose Spearman with `1/r` reaches the observed one, and the pooled Spearman over every (seed, lag) cell.
- `learn` stores each run under its `--key`, `registered` or `amended`.
- `table` reprints every number from the results JSON, the lag set's own Spearman of `r` with `n` and popcount, each stack's predictor against `n`, per-seed Spearman, the order of each adjacent pair over runs, for `field` the range over seeds at equal draws, and, post hoc, the Spearman with `1/s(n + 1)` of the ratio of `K = 3` to `K = 2` median learn time, the single-path stack taken as each lag's baseline, with and without lag `255`.

## PREDICTIONS

- Written before any run; a shifted or refitted threshold is a miss.
- F1, control: every linear arm matches `r_Q` within Monte Carlo error: median relative error at most `0.10`, correlation of `log E` with `log r` at least `0.98` where `r` varies, share of `|z| > 3` at most `0.05`, residual popcount slopes within `5%` of `log(c/(1 + c))`, flat slope of absolute value below `0.05`.
- F2: the pure ReLU `K = 3` stack follows Stern: correlation of `log E` with `log s(n + 1)` at least `0.95`, slope of `log E` on `log r` in `[0.85, 1.15]`, median relative error at most `0.20` with no fitted scale, and `r_Q` correlates better than both fitted rivals.
- F3: the residual ReLU stack keeps the popcount law: slope of `log E` on popcount within `10%` of `log(c/(1 + c)) = -0.405, -1.099, -2.197` at `c = 2, 1/2, 1/8`, `R^2` at least `0.9`, and `r_Q` correlates better than both fitted rivals.
- F4: the flat ReLU init removes the popcount bias: slope of absolute value below `0.05`.
- F5: every ReLU arm has at most `0.10` of its lags past `|z| = 3`.
- L1: SGD on the `K = 3` stack: Spearman of median learn time with `1/r` at least `0.8`.
- L2: Adam on the `K = 3` stack: that Spearman at most half the SGD value.
- L3: at `K = 3`, for both optimisers, Spearman of the median learn time with `n` and with popcount each of absolute value below `0.5`.
- L4: the SGD `K = 3` Spearman with `1/r` beats `95%` of the shuffled `r`.
- L5: under SGD at `K = 3` the higher-`r` lag of each adjacent pair learns first (`144` before `143`, `254` before `255`), and each equal-`r` pair's medians lie within a factor `1.5`.
- L6: `K = 2`: Spearman with `1/s(n + 1)` of absolute value below `0.5` for both optimisers.
- L7: `K = 4` under SGD: Spearman with `1/r_4` at least `0.5`, so a far lag learns faster.
- Amendment, written after the registered `learn` run and before the amended one, thresholds unchanged: the registered run learns every lag within `200` steps, so reads every `25` steps tie most learn times, and its SGD rule picks lr `0.3` at `K = 3` and `K = 2`, where `2` of `3` seeds diverge, leaving every `K = 3` SGD median capped. The amended run reads `f` every step, takes the largest SGD lr whose run passes the same loss test at each of the probe seeds `97, 98, 99` over `300` steps, and uses `5` seeds, which the measured `2` seconds a run allows. L1 to L7 are scored again on it; the registered run is reported as registered. The lr probe so moves from `1` seed over `100` steps to `3` seeds over `300` steps.

## RUN

- `uv run --project . python -I research/dilations/lab/py/lag-bias/lag.py field` from the repo root, `2.9` seconds, peak resident `0.259` GB.
- `uv run --project . python -I research/dilations/lab/py/lag-bias/lag.py learn`, the registered protocol, `37` seconds, peak resident `0.412` GB.
- `uv run --project . python -I research/dilations/lab/py/lag-bias/lag.py learn --key amended --every 1 --tune strict --seeds 5`, `116` seconds, peak resident `0.411` GB.
- `field --arms pure --seed s` for `s = 77, 78, 79, 80`, `1.6` seconds each; `field --arms pure --draws 4000 --seed s` for `s = 77, 79, 80`, `6.3` seconds each; `field --arms c2 --draws 3000`, `10.3` seconds; peak resident `0.261` GB.
- `uv run --project . python -I research/dilations/lab/py/lag-bias/lag.py table`, `3.3` seconds; `all` runs `field` then the registered `learn`.
- `--draws 200`, `--seed 17`, `--arms` (all), `--seeds 3`, `--cap 3000`, `--adam 0.001`, `--shuffles 10000`, `--device cpu`, `--threads 4`, `--every 25`, `--tune registered` and `--key registered` are the dials.
- One process, no workers, the MPS allocator capped at half the device; `cpu` beats `mps` on these tensors.
- Writes `results.json` under `data/research/dilations/lab/py/lag-bias/`, with the per-lag field energies and their standard errors; reads nothing else.
