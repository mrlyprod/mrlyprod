# SYSTEM

- The platform's own routes, one folder a route, `/<id>/`; any site that names `../system` in its `roots` gets them.
- mrly.net serves this folder alone; a site whose roots add `../../org/` and `../../apps/` serves MrlyProd's pages and apps beside it.
- A route is the unit an app is: `app.json`, `icon.svg`, `icon.ts` and one page of `index.tsx`, `index.md`, a `source` or `app.ts`; `../README.md` has the fields and the build checks.
- A `deep: true` route (`git`, `screensavers`, `settings`) owns every path under its route and is no scene page; the router leaves the links inside it to the page.
- A route may import `../shell/` as well as `../sdk/`: `missing` draws `Lost` from `../shell/parts.tsx`.
- A route owns its dependencies: the platform itself pulls in React and React DOM alone, and a route that imports any other package names it in its own `package.json` (`dependencies`, a type package under `devDependencies` as `@types/<name>`), the root `package.json` installs it for the monorepo at the same range, and the route loads it only when it opens; `../test/deps.test.ts` is the lane. Today: `preview` (the unified chain and KaTeX) and `git` (Shiki).
- A route reaches another route's code through its chunk, never by path: `../sdk/md/md.ts` `reader()` opens the reader's `markdown`; `git` and `../../org/research/` render README text through it.
- Route-only code sits in its folder: `git/git.ts` (the viewer's client, its own build entry) and `git/code.ts` (the Shiki highlighter), `reader/md.ts` (the markdown pipeline), `stats/stats.ts` (the poll of `/stats/stats.json` every minute, the pure views, series and facts, and `draw`), `settings/` (below).
- `stats/fixture.json` is a sample `stats.json` that `bun run dev` serves with every `at` moved to now; `../hosts/web/infra/test_stats.py` keeps its keys equal to what the Lambda returns.
- `bun test net/system` from the repo root runs their tests.

## KERNEL APPS

- A system route may hold `app.ts`: `export default app({ id, title, line, boot, verbs, moves?, read? })`, a kernel app (`../kernel/README.md`, AN APP) importing only `../sdk/system.ts` and the sdk, its id the folder's.
- Its verbs are `<app>.<verb>`, no user prefix; args are schemas of the spec's subset, with length limits on every string.
- Its state is plain JSON, pure and seeded (`ctx.draw`, never `Math.random` nor a clock): per-user data keyed by user id; the world's actors and its settled rules arrive at `boot({ seed, config, actors, rules })`, and a verb reads the rules as `ctx.rules` (`../kernel/README.md`, Rules); a rule the app cannot read stops the boot with a plain error.
- Every verb checks `ctx.who` where ownership matters and refuses with a plain note naming why; a schema can never name another user's data when the verb can act on the caller's alone (`people.rename` renames `ctx.who`).
- A per-user slice, `read: sliced((state, id) => ...)`, answers `<app>/@<id>`; the generic view shows the signed-in user that slice.
- With no `index.tsx`, the page is the generic view (`../sdk/view.tsx`): the state as a tree and each legal verb as a form; a route may add `index.tsx` beside `app.ts` for a page of its own, reading the world through `useWorld` and acting through `useCall`.
- `../hosts/local/apps.ts` installs every `app.ts`, so `mrlynet`, MCP, HTTP and the gym play it; the build collects them into `site:world`, and the site's `world.json` must name each one (the build stops otherwise).
- Proof, beside each: `app.test.ts` with a schema refusal, an ownership refusal and `../test/gym.ts` `geese`: the goose plays 10,000 seeded worlds through the gym, each replaying to its digest.
- `bot.ts`, its default export handed to `app({ ..., bot })`: the scripted policy the test users play it by (`../sdk/README.md`, WORLD, `bots.ts`); `({ state, me, actors, at, draw, world })` in, one legal `{ verb, args }` or `null` out; it reads the state the way the verbs check it, so its acts are seldom refused, and its test, `../test/gym.ts` `scripted`, plays it 150 rounds with no refusal.
- To add one: copy `messages/`, rename, write `app.ts`, `bot.ts`, `app.json`, `icon.svg`, `icon.ts`, `app.test.ts`; add its id to `world.json` `apps` and to `launchpad.json`.
- An app looks at another through `ctx.read(path)` (raw state at call time, never a slice) and changes another only by a wish, with one exception, money: a verb's `pay` moves it through the wallet in the same act (THE PAID ACT); `../sdk/system.ts` `installed` and `manuals()` are the manifests of every `app()` this host imported, for `help` and `store`.
- `../sdk/blocks.ts` is the block tree `docs`, `slides` and `sites` share: `{ kind, text, kids? }`, kinds `h1 h2 h3 p li quote code`, 3 deep, 100 blocks; `TREE` and `PATH` are its schemas.
- Not built: `bob`, the agent harness; it needs a model behind a seam, so it waits.

## THE BUS

- `noticed(called, apps)` (`../sdk/system.ts`) is the host's follow-up after each act, run by one `bus` in every host (`../hosts/local/store.ts`, the tab's `../shell/world.ts`, the gym door, `../test/gym.ts`): notice wishes, act wishes, then each installed app's `after(called)` act, so every door writes the same journal for the same acts.
- A wish of kind `act`, `act(verb, args)`, becomes that act by the same user at the same time: `term.type` runs a typed call, `code.save` writes to `files`; a world that lacks the verb's app drops it.
- The sdk names no app: `sim` declares `after`, returning `sim.tick { app, verb, ok, note? }` by the actor after every act on another app, so `sim` counts acts and refusals per app; a world without `sim` gets no extra lines.
- A follow-up's own wishes are not followed: a typed `messages.send` reaches chat, but its notice stops there.

## THE PAID ACT

- A verb may declare `pay(state, args, ctx)` beside `run`: `{ to, amount, from? }` or `null`; `from` is the caller unless named, and the caller is always one side of it (`stocks.sell`: the exchange pays the seller).
- The kernel settles it before `run`: the wallet's `money.move` takes `amount` from `from` and puts it on `to` in one step, then the verb runs on its own state; if the wallet refuses (no wallet in the world, a short balance, an amount under 1, paying yourself) or `run` refuses, the act is one refusal with that note and nothing moves: both or neither.
- One journal line as ever; the envelope carries `paid: { from, to, amount }` (`../spec/envelope.json`), and the payer's and payee's histories get one `pay` move whose note is the verb (`stocks.buy`); a paid act is private to its two sides, like `wallet.send`, never on the public `gifts` ledger.
- The `payments` rule gates `wallet.send` alone; a paid act is a purchase an app wrote, not a transfer between people, so it passes with payments off.
- A counterparty that is no person is a `reserve` of the wallet's config, funded at boot (`exchange`); a paid act to a cause raises it, as a gift does.
- Give is always public; Pay is always private.

## NOTICES

- `notifications` holds the notices other apps raise for a user; an app raises one with `ctx.wish(notice(to, text))` (`../sdk/system.ts`), a wish of kind `notice`, `{ to, text }`, the text cut to 140 characters.
- The host turns each notice wish of an accepted act into `notifications.notice { to, app, text }` by the same user at the same time (`noticed`), journaled as its own line, so a replay needs no wish; a world without `notifications` drops them, and a refused notice is dropped.
- `../hosts/local/store.ts` (so `mrlynet`, MCP, HTTP and `sim`) and the tab (`../shell/world.ts`) deliver them; the gym does not.
- `notifications.notice` is a verb like any other: anyone in the world may raise a notice for anyone, stamped with who raised it.

## CIVIC

- `wallet`, `give`, `wish`, `vote`, `feedback`, `health` and `ads`, the plain civic apps; each `bot.ts` is its test users' policy, `bot` on its `app()`, which `../sdk/kinds.ts` plays.
- Money is whole numbers in the smallest unit, never floats; one wallet each, one currency.
- Money is minted once, at boot: the `grant` rule, a whole number (or a pick of them) to each actor, plus the config's `reserves`, `supply` in all; no verb mints, and every move is one verb with the caller on one side of it, `ctx.who`, so nobody moves money between two others.
- Two rules of the world, `payments` and `gifts`, each `"on"` or `"off"` (or a pick), gate the moves between two people: `wallet.send` needs payments on, `wallet.give` to a person needs gifts on; off when the rule is missing, reality's setting; a gift to a cause always passes; the refusal names the rule ("payments between people are off in this world; give to a cause: mrlynet"); the verbs read `ctx.rules`, the bot `world.rules`.
- Causes are config (`causes`, an id to a name), held by the world; no verb takes money out of one.
- `../mrly.net/world.json` picks each rule at boot: payments and gifts on or off, a grant of 100 to 100,000 each (a whole unit a hundredth), the same for all so a run starts even, and `kinds` one of human, agent, bot or a mix; Settings > About shows the seed and what settled, `mrlynet sim` reports it.
- A kernel app sees only its own state, so a move that touches money is the wallet's own verb or a paid act (THE PAID ACT): `give` is a page over `wallet.give`; a ballot cites its wish by number and carries its question; an ad names its organisation as text; a clinic is care's own record. The bots read the whole world (`Seen.world`) and make the links.

## SETTINGS

- `../shell/panes.ts`: `PANES` (`id`, `title`, `art` a 5x5 glyph, `more` the search words, `href`), shared with the Launchpad search; each pane's hue lives in `settings/index.tsx`.
- `index.tsx`: the frame: a sidebar (search, More, one row a pane) and the pane; it catches its own links (`depth` grows on each), popstate, the title and the canonical link.
- Two columns; `/settings/` shows Appearance; Appearance draws the design's `preview` part for Auto, Light and Dark (a neutral window when it draws none) and lists the design's own knobs under its title.
- Search ranks panes by title, `more` and each pane's `FIND`; `/` or Cmd/Ctrl+F focuses it, Enter opens the first hit, Escape clears; arrows walk the list.
- More: Copy settings link (`share`), Export settings (`<prefix>settings.json` of `pack()`, `mrly-settings.json` on mrly.net), Import settings (`unpack`, then reload).
- `/settings/?apply=<code>` asks before it applies a shared link (`unpack(decode(code))`); a bad code says the link is broken.
- `ui.tsx`: the kit every pane draws with: `Pane`, `Section`, `Item`, `Switch`, `Select`, `Segment`, `Tiles`, `Swatches`, `Action`, `Nav`, `Note`, `Glyph` (a 5x5 art string as pixels).
- A system app never names a design nor the brand: the site config holds it (`site.title`, `site.mark`), and a saver whose host is no route wears the tiles glyph.
- `use.ts`: `usePref(key)` (a storage key, live).
- One file a pane (`<id>.tsx`): `default function Pane({ site })` and `FIND`, the labels search reads; the styles are `../../designs/shared/settings.css`.
