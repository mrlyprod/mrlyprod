# ui

- mrly.net's own design kit, not a package: plain CSS, a little vanilla JS, a little React. No build step, no Tailwind, no CSS-in-JS.
- House style: palette first (the fifteen colors and a link shade per hue, generated), theme and tokens second (`tokens.css`, by hand), one class per idea, semantic HTML, light on `:root` and dark twice (`prefers-color-scheme` guarded by `:root:not([data-theme="light"])`, then `:root[data-theme="dark"]`), AA contrast in both, 44px targets on coarse pointers, no motion under `prefers-reduced-motion`.
- The palette and the two role sets sit in the kit beside this folder: `../kit/palette.css`, `../kit/theme/palette.js` and `../kit/theme/theme.js`, generated, never hand-edited.
- The code viewer's skin sits there too, `../kit/code/code.css` and `../kit/code/seti/`: it reads this folder's tokens.
- The palette names black, white and thirteen hues (`--red --orange --yellow --green --mint --teal --cyan --blue --indigo --purple --pink --brown --gray`), one flat value each; each tint hue also gets `--<hue>-link`, the hue darkened in light (and lightened in dark only if it fails) until it reaches 4.5:1 on `--bg`.
- `tokens.css` resolves the roles `--ground --bg --panel --deep --line --fg --dim --accent --link --on-accent` per theme.
- `--art` is `var(--ground)`, the ground of every canvas and figure; a figure pair ships as one `<picture>`, the dark WebP in `<source media="screen and (prefers-color-scheme: dark)">` and the light WebP in the `<img>`, so only one half is fetched and print takes the light one.
- `chrome.js` fires `window` event `theme` whenever `data-theme` or `data-tint` changes; scripts that paint with `palette.js` listen and repaint.
- `config.js` `headScript(prefix)` is a tiny inline script for the `<head>`, before any stylesheet: it adds class `js` and replays `data-theme`, `data-font` and `data-tint` from localStorage, so a page never flashes the wrong theme.
- Tint is a runtime setting: `data-tint` on `html` is a palette hue name, absent means the site default, and `tintCss(hue)` writes the site default plus a `:root[data-tint=<hue>]` block for every hue but grey.
- A tint is the plain hue on both grounds; `--on-accent` is white and `--ring` follows `--accent`. `--link` is the tint's `--<hue>-link` shade, the colour of `a`.

## CHROME

- One frame: `--frame` = `--page` + `--side`, with `--side` a fixed 16rem so a bar and the stage beside it land on whole pixels. It caps the header, the subheader and the block under them, so the two bars sit the same on every page.
- At and above 74rem `.panes` is one flex row, centred: main alone on a page with no bar, main and the bar as one block on a page with one, and on `/git/` the explorer before main. No column is kept empty. Below 74rem a pane is a drawer.
- The right bar is by need: `Shell` draws `aside.pane.right`, its opener in the subheader and the scrim only for `controls` or a contents list that `fills` (`bar.js`: three items or more). A page with neither has no pane, no button and no scrim.
- One markup, three looks: a sticky bar at and above 74rem; below it a drawer with JavaScript; below it without JavaScript the same aside in flow above main (`order: -1`).
- The contents list is one closed `<details>`: `chrome.js` opens it, the wide sheet shows it through `::details-content` before any script runs, and on a narrow screen without JavaScript it stays one collapsed line.
- A demo's bar is a slot its page fills in the browser; without JavaScript a pane that holds only an empty slot is not drawn.
- `/git/`: the built shell holds the explorer and no right pane, its right button written `hidden` with the rule as `data-few`. `lib/git.js` reads that number, makes the pane and shows the button when the file it draws has that many headings, and takes both away when not.
- Two bars. The header is three plain links in the pixel font and nothing else: `+` to `menu`, the middle to `/`, `O` to `cart`; it scrolls away.
- The middle names the app: the X on `/`, elsewhere the lowercase name of the deepest menu door whose href starts the route, else the route's first segment (`word.js`, one rule for the build and the browser). `chrome.js` re-reads it on every `wire`, so a router hop renames it; a mouse hover plays `fold` from `font.js`, the letters merging into the X, reversed on leave, still under reduced motion.
- Header glyphs are drawn at a whole `--cell` of 3px a cell (`--rows` and `--cols` on each svg), so every pixel of the font stays square. `+` and `O` are page links like any other: a hover fetches `/menu/` or `/cart/` ahead, a click pushes and swaps (ROUTER), and Back returns to the page left, at its spot. The subheader under it is sticky on every page: crumbs on the left, an actions slot on the right. It never repeats menu, home or cart.
- A crumb is read from the page's own path by `crumbs.js` and from nothing else: one link per folder, the segment as its text, the last the page itself with `aria-current`. Home and `/404.html` have none. On `/git/` `lib/git.js` writes them again from the address bar on every view.
- The actions slot is `div.actions`, empty unless the route fills it: the right pane's opener on a page with a bar, and on `/git/` the explorer's opener before it. An opener is `Opener({ side, label, icon, few })` of `lib/frame.jsx`, a 20 px icon of `lib/icons.js` (`paneLeft`, `paneRight` here, the frame's own below), `few` writing it hidden with `data-few`, shown only below 74rem and only with JavaScript; it rests at 0.6 opacity and an open drawer lifts its button to full.
- Opening a drawer moves focus to its first link, button or field at once, and Escape hands it back to the opener: the open rule transitions the transform alone, so `visibility` flips with no delay, and under reduced motion nothing inside a pane transitions, since the reset's 0.01ms on every element would pass an inherited `visibility` down one level a frame.
- The scroll rule: `chrome.js` keeps `scrollY` per `location.href` in sessionStorage on `pagehide`, then on `load` drops the key and puts the spot back only on a back-forward or a reload with no hash, so a fresh load never scrolls itself; opening a drawer pins the subheader to the viewport top so the drawers hang from the bar.
- The `O` is the font's O around nine inner cells; `chrome.js` lights one cell per item in the cart, read from localStorage `${prefix}cart` (an array of `{ qty }`), and repaints on the `cart`, `storage` and `pageshow` events.
- Drawer state lives as `data-left` / `data-right` = `open` | `shut` on `html`, never persisted. Theme is `data-theme` = `light` | `dark` (absent = auto), font is `data-font` = `sans` | `serif` | `mono` | `mrly` (absent = Default: Noto Sans, Noto Serif in `.prose`), tint is `data-tint` = a hue name (absent = the site's), all three in localStorage under `prefix`. The saver pick is no attribute: `${prefix}saver` holds `''` (none), `random`, an app id or `id?query`; `screen()` in `chrome.js` writes it from the Settings select and from the window `saver` event a saver page fires, and names no saver. `html.js` marks a page with JS, set by the boot script before the first frame.
- Settings, on `/settings/` alone: `Settings()` is the kit of `lib/knobs.jsx` in one `section.controls`, two `Group`s, Appearance (Theme, Font, Tint) and Screensaver (Saver), each row a label left and its value right. Theme is a `Btn` with `data-theme-toggle` cycling auto, light, dark; Font, Tint and Saver are `Pick`s whose `data-*-pick` and `defaultValue` pass through to the select, Auto first on Tint; without JavaScript the rows show dimmed and take no pointer under the noscript line; on Saver None, Random, then each `saver` row of `apps/apps.json`, handed in by the build as `Settings({ savers })`; every option a plain word. `tokens.css` maps `data-font` to `--face`; `base.css` sets body and `.prose` in `var(--face, ...)`, and one `chrome.css` rule sets the chrome (`.skip .top .subheader .pane .frame .base`) in `var(--sans)`, so the chrome stays Noto Sans and only the reading text changes.
- The tree takes nodes `{ name, href?, nodes?, lazy?, icon? }` and shows them as given; only the code viewer hands it any. A branch is open only when it holds the current page, nothing else is open by default. `icon` is a seti class drawn before the name. A node with `lazy` renders a `<details data-lazy="path">` whose children arrive on first open from the JSON at `/git.json` (`{ base, c: [{ n, k: d|f, i?, c? }] }`, `i` the seti kind); the arrow expands, the name navigates. On a code page the tree is the repository alone, root first, the path to the page open, so the viewer reads like an editor.
- KNOBS: every `.controls` (a Frame's right bar, Settings) wears one look: a `Group` is a small-caps heading over a column of rows; a row is a hairline pill, label left and control right; a select or a field sits borderless on the right, a slider puts its number, with the row's `unit` after it, on the label's line and its track under it, a check or a `Toggle` (`role=switch`, writes 0 or 1) sits right, a `Segment` is a radio group of up to four, a list is a column of `Toggle`s whose last one on stays on, disabled, so a list is never empty; a button fills the row, a `b` inside it reads as the value, and a `Btn` a pointer clicks lets go of focus after its action. `Knob({ row, value, onChange })` draws one spec row through `tidy`, `Knobs` every group of a spec. `Export` is a `Btn` with the export icon and a native popover of PNG and WebP calling `save()` of `lib/export.js`; where anchor positioning is missing the popover sits above the frame's bottom bar at its right end.
- KEYS: `useKeys(map, acts)` binds one window keydown per island through `hit()` of `lib/keys.js`, any open dialog but the keys card swallowing keys, and a key typed in a field or pressed on a control inside a `.controls` staying with it; `?` opens `Keys`, a native dialog card (`--float`) of keycaps in words beside each action, its Escape shutting the card alone, never a drawer under it (`chrome.js`); `Hints` is the first three rows for the bottom bar's `div.hints`, hidden where nothing hovers.
- FRAME: `Frame({ label, gestures, children })` is `section.frame`, one grid: left bar, stage, right bar over a bottom row (`div.status`, `div.hints`, `div.actions`, one class per `Bar` side, then the openers below 74rem). `Bar({ side })` claims a side and portals into it, so a side nothing fills is not drawn; outside a Frame a right `Bar` lands in the shell's `#right .controls`. The bars are Shell's `aside.pane` markup, so the drawers, Escape and stow serve them; at and above 74rem they dock at `--side` beside a flush stage, below it they hang from the frame between the subheader and the bottom bar, and under 40rem the right bar is a non-modal sheet of `--sheet` over the live stage, which shrinks to the room above it so a scene refits, closed by its opener, Done or Escape; Done and Escape hand focus back to the opener. The right bar blurs a control after a pointer changes it and never after a key steps it. The status bar is a row of items, the last one cut with an ellipsis before the rest (the seed goes first, the score stays), and under 40rem it takes whatever width the actions leave; in the actions bar a `.primary` button leads. The frame fills the screen under the two heads and the footer hides.
- The footer is the legal line alone: `Copyright © {company} {since}-{year}. All rights reserved.` No links: the menu page holds them.
- `Grid({ nodes })` is the one gallery: a node with `figure: { dark, light }` is a picture tile, `text` its caption, `dates` its stamps, a node without a figure a plain tile. Every index page, the demo gallery, the home doors and the menu draw it, so they all look the same.
- `Menu({ tree })` lays two levels out: one `Grid` of the top level, a node with `nodes` a folder whose tile links `#<name>`, then one `<section id="<name>">` per folder, a plain heading over a `Grid` of its nodes. Inside `.menu` a grid's columns start at 6rem, so a tile is an icon and its label. `/menu/` is that over the `tree` of `site.json`, every node dressed with a figure; `island` and `search` are written on the `div.menu` for the search bar.
- Print is one story in three files: `base.css` sets the page margin, black on white, 11pt, the light figure of every pair, the read column full width, headings kept with their text, figures, tables, code and block math unbroken, code wrapped, and every link's target in brackets after it; `chrome.css` turns the skip link, both bars, both panes, the scrim, the footer and the lock off, lets main fill the sheet and keeps the opener at 20rem; the kit's `code.css` drops the line numbers and the code frame and wraps long lines. Nothing is hidden but the chrome: a paper or a note prints from the browser as it reads.
- The opener is the page's own figure over the title: one `figure.opener`, at most 32rem wide, centred, hairline framed on the `--art` ground.

## HOME

- `/` is the welcome's hall, then `section.heroes`, `section.shelf` and `div.home` (newest claim, latest papers, what is MrlyMath). No right bar.
- A hero is one `a.hero` per row of `heroes` in `site.json` (`name href line hues seed`): `div.art`, then `div.plate` holding an `h2` and one `p` in Noto Sans. The hero is its art's size and nothing else: as wide as the page up to 3072 px (16 cells of 192), rounded down to a whole 16 px (9 px in portrait) so every cell is an integer number of pixels, centred on an integer margin when the bound binds. Its height follows from 16:9 (9:16), taller than the screen if it must be. The heroes are a flush column with one gap (`--gap`, one `--s4`) between blocks, above the first and below the last. Nothing snaps.
- The art is pure CSS: 144 empty `<i>` cells (72 on a tile), 16 by 9, or 9 by 16 in portrait (`grid-auto-flow: column` transposes it), whole cells with no gap and never cropped. A cell's one-letter class names its hue (`pages.css` maps them); `a` is `--accent`, so the art follows the tint.
- The build rolls the cells from the row's `seed`: a blocky gradient through `hues` in order along a random direction, dithered in 2 by 2 blocks, with at least eight accent cells (four on a tile). Same seed, same art; a new seed rerolls.
- The shimmer is one keyframe: each cell lightens in turn, its delay read from `sibling-index()` over `--across` (16, or 8 on a tile), a diagonal wave every 6 s. None under reduced motion or where `sibling-index()` is missing.
- The hero is a 16 by 9 grid (9 by 16 in portrait) and the art a subgrid of it, so the plate, a sibling of the art outside its `aria-hidden`, spans whole cells: 6 by 2 (7 by 3 in portrait) from a start the build rolls from the seed after the cells. The start is inline as `--col --row` and, since the browser picks the orientation, `--pcol --prow`; each keeps the plate inside the grid. The plate is a flat `--bg` fill, no border, square corners; its text scales with `--cell`. On hover or focus the cells touching it light up in the tint: a box-shadow spread one `--cell` wide, so whole cells, clipped at the edge by the paint containment `content-visibility` brings.
- Full bleed: on `/` main and `.panes` drop their caps (`chrome.css`); `.shelf` and `.home` put the page width back.
- The shelf is the padded grid section: the tree's top level less Home and the heroes, in tree order, one `a.half` each; a folder links its section of the menu.
- A half hero is 8 by 9 cells (9 by 8, one column, under 40rem): art rolled from a seed hashed from the door's name through the `hues` of its row in `tiles` of `site.json` (`name hues`), and a 5 by 1 plate holding the name. A missing row, or a row naming no shelf door, stops the build.
- Two columns with the hero gap between; a tile is (inner width - gap) / 2 rounded down to 8 px (the width to 9 px on a phone), the pair centred on an integer `--lead`.

## ROUTER

- `router.js` makes the visit one document: a click on a page link fetches that page's HTML and swaps it in. Without JavaScript every link is a page load.
- A page is a same-origin path that ends in `/`, or any path under a deep prefix (`/git/`). The prefixes are the one key the router reads, `<html data-deep>`, written at build from `modes`.
- Left to the browser: another origin, a `target`, a `download`, a modified click, a file (`robots.txt`, a pdf, all of `/raw/`) and a `#fragment` of the page it is on.
- Left to the page's own router: a link under the deep prefix the page is already in. Inside `/git/` the viewer takes every `/git/` link and every pop between them.
- `pointerenter` and `focus` on a page link fetch its HTML ahead of the click; the cache serves a push for 30 seconds and a pop at any age.
- The swap is one task: the title, the head's `meta[name]`, `meta[property]`, canonical, JSON-LD and modulepreload lines, the stylesheets (the next page's are loaded switched off first) and every node between the header and the footer. Then both drawers shut, a `wire` event, and focus on `<main>`.
- Islands: the next page's entries are imported before the swap, the old page's are unmounted first thing in it, the new ones mounted last. A page entered twice mounts twice.
- Scroll: a push opens at the top, or on its `#fragment`; a pop returns to its spot. The spot is `y` in the entry's `history.state`, written before a push, before the old islands unmount and only while the address is still the page on screen, and on `scrollend` while nothing is `aria-busy`. The `/git/` viewer writes the same key, and `stamp` in `lib/query.js` hands the state and the hash through.
- While `html` is `aria-busy` the address can be ahead of the page on screen (a pop still loading): `stamp` writes nothing then, and `chrome.js` keeps no scroll spot at `pagehide`. A full load that resumes an entry lands on the spot `chrome.js` kept, else on the entry's `y`.
- The last ask wins: a click or a pop cancels whatever hop is still loading, and a pop back onto the page on screen cancels it too. A page restored from the back/forward cache drops `aria-busy`.
- `html` is `aria-busy` from the click until the islands are up. Motion is one View Transition around the swap, none under reduced motion.
- Any failure is a plain load of the same url: a fetch that fails, an error status, a redirect, an answer that is not HTML, a page with no header or footer, a page whose head names other site scripts than the ones running (a deploy changed the chrome or the router; a script from another origin, as an extension leaves, is not read), a stylesheet or an entry that does not load, an entry whose bytes changed, a mount that throws.
- A link to the page on screen enters it again, in the same document, replacing its entry.

## SEARCH

- `search.js` is an island: the menu's `div.menu` names it and lists the indexes that exist in `data-search`, `/search.json` today. The built page holds no field: without JavaScript nothing of the bar is there.
- `mount` puts one `form[role=search]` first in the menu, an `input[type=search]` over an empty grid, on `/menu/`. On a device that hovers the field takes focus on arrival, by a load or a router hop, so `+` then letters searches with no click; on touch it waits for a tap, so no keyboard springs up; it leaves focus alone when anything but the page or `<main>` holds it.
- The indexes are fetched on the field's first focus, once per visit; one that fails is asked again on the next focus.
- A row is `[title, route, icon]`, the icon a figure name the tile draws as `/figures/<icon>-dark.webp` and `-light.webp`.
- Every word of the query must be in a row's title or route, any case, any order. The menu's own tiles are matched first, so `/cart/`, `/stats/`, the root files and the socials are found too; then the index rows, in route order, 24 tiles at most.
- Results are the menu's own tile markup in the same grid, inside the form; while a query stands every other child of the menu is `hidden`, and an empty field brings the menu back. The menu's own tiles answer at once and the index rows join when it lands. A `role="status"` line under the grid says the count, the cap or that nothing was found.
- Enter follows the first result; a result is a plain link, so the router takes it. Escape empties a filled field.
- The shop plugs in at the build: a route at `/shop/search.json` adds that path to `data-search`, and the field reads every path listed.

## FOOTER

- `footer.base` holds `p.legal.fine` and nothing else; `router.js` reads the element as the end of its swap span, so every page keeps it.

## FILES

- `tokens.css`: joined after the kit's `palette.css`; the roles light on `:root` and dark twice, `--art --scrim --mix`, type (the shipped Noto face first, then the system stack, then Noto Symbols 2 and Noto Color Emoji), the scale `--t1` to `--t7` (11 12 13 15 17 20 28 px, in rem; `--text` is `--t4`, `--read-text` `--t5`) and `--lh1` to `--lh3` (1.2 1.4 1.6), `--face` per `data-font`, space, shape with `--float` (a hairline ring and one soft shadow in light, the ring alone in dark, for a layer over a canvas), frame (`--head --foot --side --sheet`), layer (`--z-plate --z-scrim --z-drawer --z-sheet --z-bar --z-lock --z-welcome --z-skip`) and motion. `css.test.ts` holds `chrome.css`, `base.css`, `pages.css` and `../lib/mrly.css` to no px font size and no bare z-index, and every `--t`, `--lh` and `--z` they read to a definition here.
- One stylesheet per page, joined by the `sheets` block in `site.json`, in this order: `palette.css`, `tokens.css`, `base.css`, `chrome.css`, `fonts/fonts.css`, `pages.css`. That is `page.css`; `git.css` adds the code viewer's `code.css` and `seti.css`; a demo shell links `fonts.css` beside its bundled `lib/mrly.css`.
- `pages.css`: what the chrome has no rule for: the home's heroes and shelf, print for them, the plates, the widget figure and the wiki graph. The gallery tiles and the openers are `chrome.css` (GRID, GALLERY, OPENER), and the rules for a page holding a frame (full width, no padding, the phone actions) are its FRAME.
- `base.css`: reset, text, links, focus, `.prose`, reduced motion, print.
- `chrome.css`: the chrome's face, skip link, `.top` header, `.subheader` bar with its `.crumbs` and `.actions`, `.panes` with `.pane.left` / `.pane.right` and `.scrim`, `.tree`, `.contents`, `.menu`, `.base` footer, KNOBS (`.row`, `.set`, label, select, range, checkbox and switch, `button`, `.button` and `.icon`, `.tabs`, the `.controls` look, `.segment`, the `.formats` popover), KEYS (`dialog.keys`, `kbd`, `.hints`), FRAME (`.frame` and its `.canvas`, bars, `.bottom` with `.status`, `.hints` and `.actions`, the sheet, and the page around a frame), `.stats`, `.chip`, `.badge`, tables, `.cards`, `.gallery` / `.tile`, `.opener`, and the chrome's print rules.
- `chrome.js`: vanilla ESM, runs on load; the scroll spot, drawers, theme, the `<picture>` halves under a `data-theme` override, font, tint, the saver pick, cart, contents highlight, lazy tree; a page that draws a contents list later fires a `wire` event on `window` and the chrome wires it.
- `../kit/font/font.js`: vanilla ESM, the pixel font and its choreography, in the kit. The crate `pkgs/mrlyrs` is the source of truth: `scripts/wasm.sh` runs its `book` example into `site/kit/font/font.json`. `font.js` reads the book and ports only the arithmetic: the layout, the write, the phased merge that folds the letters into one centred stack, and the fold that ends on the X. It uses the wasm bridge `globalThis.mrly.font_*` when present; `../kit/font/font.test.js` pins the crate's numbers and checks every frame against the wasm, and skips itself where `site/pkg` is absent.
- `../kit/font/font.json`: generated by the crate, `{ char: { rows, path } }`, the bitmap rows and the cell-by-cell stroke order over the trimmed glyph.
- `islands.js`: vanilla ESM, the island loader; `router.js` imports it, so every page holds the same one (the site README has the contract).
- `router.js`: vanilla ESM, the site router, on every page after `chrome.js`; ROUTER below.
- `stats.js`: vanilla ESM, an island; `/stats/` names it and it polls `/stats/stats.json` into the two `[data-stats]` mounts under its host, reusing `.table`, `.prose` and `.fine` and adding no CSS.
- `claims.js`: vanilla ESM, an island; a claims page's `form.filter` names it and it filters the page's `section.claims` by tag chip and by date, reading the pressed chip back from the markup.
- `search.js`: vanilla ESM, an island; SEARCH above.
- `logo.js`: the MrlyLogo mask, which is the font's `X`, plus `grid(level)` and `logoSvg(level, fill, ground)`; the builder draws the favicon and the icons from it.
- `chrome.jsx`: React, renders the whole page at build for `react-dom/server`; no browser bundle imports it.
- `contents.jsx`: the contents list alone, a closed `<details>`, nothing under three items; the one part a demo also draws in the browser.
- `bar.js`: the bar's one rule, `FEW` and `fills(items)`; `chrome.jsx` and `contents.jsx` import it, and no other browser entry does, so it never becomes a chunk of its own.
- `crumbs.js`: the subheader's one rule, `crumbs(path)`; `chrome.jsx` reads it at build and `lib/git.js` in the browser.
- `hues.js`: `HUES`, the twelve tint names, and `tints(blank)`, the options of a tint pick with `blank` for `''`; a leaf that `config.js`, `chrome.jsx` and `lib/scene.js` import, so the browser gets it without the config.
- `config.js`: `configure(site)` takes `site.json`, `conf()` reads it back, `tintCss()` writes the accent blocks, `headScript()` writes the boot script. Keys the kit itself reads: `title since prefix tint menu cart company`.
- `fonts/`: `fonts.css` and the faces, all OFL with their licences beside them: Noto Sans, Noto Serif and Noto Sans Mono (variable 400-700, Latin), MrlyFont from `pkgs/mrlyrs`, Noto Sans Symbols 2, and Noto Color Emoji in eleven unicode-range shards. `site.json` lists them under an `assets` bundle with `hash: true`, the builder rewrites each `url()` in the css to the hashed name, and `fonts.css` rides inside the page's one sheet; a face is fetched only when a page needs it.
- `bun run vendor` writes `fonts.css` whole from the `fonts` block in `site.json`: the Google families first, then `fonts/keep.css` verbatim, the two faces this site cuts itself, so `mrly.woff2` and `symbols.woff2` survive every run. Add a shard or a family there, not by hand, and list the new file in the `assets` bundle.
- `symbols.woff2` is cut from the master at `files/fonts/symbols.ttf` down to the glyphs the built pages print, with `bun run symbols`, which rewrites its `src` and `unicode-range` in both `keep.css` and `fonts.css`; `fonts.test.ts` fails if a built page prints a codepoint no shipped face draws and its `KNOWN` list does not name.

## EXPORTS

- `../kit/font/font.js`: `letters(text)` gives `{ rows, cols, grid }`; `animate(text, pad)` writes, `merge(text, pad)` folds; `fold(text, into, pad)` merges and lands on `into`, the X by default, as `{ rows, cols, fps, frames }`.
- `chrome.js`: none; it boots when loaded. Its `wire()` is idempotent: it syncs aria state, stops the contents observer of whatever left the document, applies theme, font, tint and the saver pick, paints the cart, and attaches the contents observer, and a `wire` event on `window` runs it again.
- `islands.js`: `load(root = document)`, `mount(root = document)` and `unmount(root = document)`.
- `router.js`: `go(url, mode = 'push')` and the rule alone, `sort(to, from, deep)` and `walled(path, deep)`; it boots when loaded.
- `stats.js`, `claims.js`, `search.js`: `mount(host)` and `unmount(host)`; `search.js` also the rule alone, `terms(query)` and `meets(words, text)`.
- `crumbs.js`: `crumbs(path)` gives `[{ name, href }]`, one per folder of the path; a path with no closing slash ends on the file itself.
- `hues.js`: `HUES`, `tints(blank)`.
- `config.js`: `configure(site)`, `conf()`, `tintCss(hue)`, `headScript(prefix)`, `inlineScripts(prefix)`, the boot list: the one inline script a page may carry.
- `chrome.jsx`: `Shell({ route, tree, current, contents, controls, late, wide, children })`, where `route` gives the subheader its crumbs, `tree` draws the left pane and its opener only when it holds nodes, `controls` or three `contents` items draw the right pane, `controls: true` leaves an empty slot in it and `late` writes the right button hidden, with `data-few`, for a page that makes its bar in the browser, `Grid({ nodes })`, `Menu({ tree, island, search })`, `Settings({ savers })`; the header, subheader, tree, contents, controls and footer are Shell's own parts, not doors.
- The header always draws the site's wordmark; `prefix` moves the localStorage keys and is read in the browser from `<html data-prefix>`.
